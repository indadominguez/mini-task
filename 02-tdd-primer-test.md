## Code-along: modelo de datos y primer test

Partimos del proyecto creado en la sesión 1. Todavía no tiene lógica de negocio — crearemos la primera entidad y su test con TDD.

### 1. Pensar qué queremos probar

En Battleship necesitamos una entidad `Game` que represente una partida. Para empezar:

- Una partida tiene un estado (`PENDING`, `IN_PROGRESS`, `FINISHED`)
- Al crearse, su estado inicial es `PENDING`

Escribimos el test **antes** de crear la entidad.

### 2. Red — el test que falla

```java
package com.example.battleship.domain;

import org.junit.jupiter.api.Test;
import static org.assertj.core.api.Assertions.assertThat;

class GameTest {

    @Test
    void newGameShouldBePending() {
        var game = new Game();
        assertThat(game.getStatus()).isEqualTo(GameStatus.PENDING);
    }
}
```

**Ejecutar:**

```bash
mvn test
```

Falla porque `Game` y `GameStatus` no existen. Rojo.

### 3. Verde — lo mínimo para que compile y pase

```java
package com.example.battleship.domain;

public enum GameStatus {
    PENDING, IN_PROGRESS, FINISHED
}
```

```java
package com.example.battleship.domain;

import jakarta.persistence.*;

@Entity
@Table(name = "games")
public class Game {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Enumerated(EnumType.STRING)
    private GameStatus status;

    public Game() {
        this.status = GameStatus.PENDING;
    }

    public GameStatus getStatus() {
        return status;
    }

    public Long getId() {
        return id;
    }
}
```

En clase, señalar:

- `@Entity`, `@Id`, `@GeneratedValue` — anotaciones JPA básicas
- `@Enumerated(EnumType.STRING)` — guarda el nombre del enum, no su ordinal
- `@Table(name = "games")` — personaliza el nombre de tabla
- Constructor sin args requerido por JPA, inicializa `status` por defecto

**Ejecutar otra vez:**

```bash
mvn test
```

Pasa. Verde.

### 4. Blue — refactorizar

Por ahora no hay nada que refactorizar. Pero planteamos la pregunta: ¿tiene sentido que `Game` sea un record de Java en lugar de una clase? Discutimos:

- Los records son inmutables por defecto
- JPA necesita mutabilidad (`@Entity` no admite `record`)
- Para entidades JPA seguimos con clase tradicional

Decisión: dejamos clase, pero usaremos records para DTOs más adelante.

### 5. Migración de base de datos con Flyway

Creamos la primera migración para que H2 tenga la tabla `games`:

`src/main/resources/db/migration/V1__create_games_table.sql`

```sql
CREATE TABLE games (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    status VARCHAR(20) NOT NULL
);
```

**Ejecutar la aplicación:**

```bash
mvn spring-boot:run
```

Verificar:

- Log: `Successfully applied 1 migration to schema "PUBLIC"`
- Consola H2 → tabla `GAMES` existe con columnas `ID` y `STATUS`

Si hay error, revisar que `spring.jpa.hibernate.ddl-auto` está en `validate` (no crea tablas por su cuenta).

## Lo que vimos hoy

| Concepto | Dónde se ve |
|----------|-------------|
| Ciclo TDD (rojo-verde-azul) | `GameTest` → crear entidad |
| `@Entity`, `@Id`, `@GeneratedValue` | Mapeo JPA |
| `@Enumerated` | Enums en JPA |
| `@Table` | Personalizar nombre de tabla |
| Flyway | `V1__create_games_table.sql` |
| AssertJ | `assertThat(...).isEqualTo(...)` |
